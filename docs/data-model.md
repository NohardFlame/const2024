# Модель данных

## Текущий формат

Файлы: [`assets/json/const0.json`](../assets/json/const0.json) … [`const9.json`](../assets/json/const9.json).

```json
{
  "number": 0,
  "vert": [
    [x, y],
    [x, y, "Имя Фамилия", "Текст достижения"],
    ...
  ]
}
```

| Поле | Смысл |
| --- | --- |
| `number` | Сколько **первых** звёзд в массиве `vert` считаются зажжёнными (имеют достижение). Шейдер сравнивает индекс звезды с `last_lit = number - 1`. |
| `vert[i][0]`, `vert[i][1]` | Нормализованные координаты цели (`≈ [-1, 1]`), до экранного масштаба в `dataHandler.setup` / `update_all`. |
| `vert[i][2]` | Заголовок (имя / «ЗВЕЗДА»). Пусто или `"DELETED"` — звезда не зажжена. |
| `vert[i][3]` | Текст достижения. |
| `vert[i][4]` | Опциональный якорь `STAR` (`s01`…) для повторного импорта из таблицы; координаты не меняет. |

Зажжение считается **по полям `[2]`/`[3]` на конкретной вершине**, а не по префиксу `number`. Поле `number` синхронизируется как счётчик зажжённых (совместимость). Редактор больше не делает `swap_stars`.

### Как редактор меняет данные

- Добавление / правка: пишет `[2]` и `[3]`, при необходимости увеличивает `number` и **меняет местами** элементы массива (`swap_stars`), чтобы зажжённые шли с начала.
- Удаление: уменьшает `number`, ставит `"DELETED"` в текст, снова swap.

Следствие: достижение привязано не к «выбранной точке фигуры», а к позиции в упорядоченном префиксе массива. После swap геометрия точек на экране меняет «кто где стоит» относительно силуэта.

### Связанные ассеты (не в JSON)

| Ресурс | Связь |
| --- | --- |
| `assets/textures/texN.png` | Пунктирный силуэт созвездия `N` (линии + иногда текст, как год на `tex9`) |
| `assets/textures/class_texture.png` | Атлас иконок классов 3×3 |
| `assets/textures/star_texture.png` | Атлас видов звезды (пустая / зажжённая / активная) |
| SVG в `assets/textures/` | Исходники фигур для генерации вершин; в рантайме доска их не читает |
| [`svg_parser.js`](../assets/js/svg_parser.js) | Офлайн: path → уникальные нормализованные точки → вставка в JSON |

Индекс `N` сейчас — магическое число: один и тот же `N` связывает JSON, PNG и клетку сетки (для 0–8). Имена классов и год учебного периода в данных **не** хранятся.

## Проблемы текущей схемы

1. **Геометрия и контент смешаны** в одном массиве; удаление/вставка ломают соответствие «точка на контуре ↔ человек».
2. **`number` как префикс** мешает зажигать произвольные узлы фигуры (хвост, глаза, лапы) без перестановки координат.
3. **Нет идентификаторов** класса и звезды — только индекс файла.
4. **Нет метаданных** (название класса, учебный год, порядок в сетке) — они в PNG и в хардкоде UI.
5. **Дублирование на клиенте:** `origN` (для сохранения) и `vertN` (для отрисовки) — две копии одного JSON в памяти и два HTTP-запроса при загрузке.

## Предлагаемая схема

Цель: разделить «точки фигуры» и «достижения», сохранить идею именованных звёзд, упростить редактор и миграцию рендера.

### Манифест (один файл или каталог по классам)

```json
{
  "version": 2,
  "schoolYear": "2025-2026",
  "home": {
    "id": "lyceum",
    "silhouette": "textures/tex9.png",
    "stars": [ { "x": 0.1, "y": 0.2 } ]
  },
  "classes": [
    {
      "id": "2-1",
      "label": "2¹",
      "gridIndex": 6,
      "silhouette": "textures/tex6.png",
      "iconCell": { "col": 0, "row": 2 },
      "stars": [
        {
          "id": "s001",
          "x": -0.12,
          "y": 0.45,
          "lit": true,
          "title": "Иванов Артём",
          "text": "Победитель школьной олимпиады по математике"
        },
        {
          "id": "s002",
          "x": 0.33,
          "y": -0.1,
          "lit": false
        }
      ]
    }
  ]
}
```

### Правила

| Правило | Зачем |
| --- | --- |
| У каждой звезды стабильный `id` | Правка текста не двигает точку; сортировка UI не ломает геометрию |
| `lit` / наличие `title` вместо префикса `number` | Можно зажечь любую точку контура |
| `gridIndex` и `label` в данных | Сетка и подписи не только в PNG |
| `home` отдельно от `classes` | Явный домашний экран вместо «магической десятой» |
| Координаты только `x,y` нормализованные | Рендер сам масштабирует под карточки / aspect ratio |
| Силуэт — путь к ассету | Можно менять PNG без смены схемы |

### Миграция со старого JSON

1. Прочитать `constN.json`.
2. Каждую пару `[x,y]` → звезда `{ id, x, y, lit: false }`.
3. Для `i < number`, если есть `[2]`/`[3]` → `lit: true`, `title`, `text`.
4. Задать `id` класса и `gridIndex` по таблице соответствия (зафиксировать в манифесте один раз).
5. `const9` → блок `home` (без карточек достижений, либо с опциональным контентом позже).

Обратная совместимость на переходный период: загрузчик может принимать и v1 (`number`+`vert`), и v2 (манифест), пока редактор и доска не переведены целиком.

### Что не класть в JSON

- Предрасчитанные кадры анимации — считаются на клиенте или в шейдере.
- Пиксельные экранные координаты — только нормализованные.
- Бинарные текстуры — только пути.

## Контракт для UI (независим от формата файла)

Поведение, которое нельзя потерять при смене схемы:

1. Список классов с иконками; выбор класса.
2. Морф: россыпь → фигура выбранного класса (и обратно при смене).
3. У зажжённой звезды — имя и текст; выбор звезды подсвечивает её и показывает карточку.
4. Домашний экран с контуром лицея при старте (или явное «домой»).
